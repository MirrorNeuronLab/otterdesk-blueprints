# Task goal

**Section:** 23 · Implementation-ready work packages  
**Specification ID:** `AR-23-01`  
**Customer question:** What single outcome should this work package deliver?

## What to include

- Assign a stable work-package ID and link it to a recommendation, finding, and migration stage.
- Describe the intended architectural or behavioral outcome in concrete terms.
- State the current problem, target condition, and why this unit of work is appropriately bounded.
- Record approval status and whether the task is investigation, implementation, migration, or validation.

## Why this matters

A clear goal lets a human or coding agent optimize for the intended result rather than make broad opportunistic changes. It also gives reviewers a stable reference for deciding whether the task is complete.

## Evidence to use

Use the selected recommendation, scoped finding, approved constraints, and staged roadmap. Mark proposed tasks as unapproved until a customer decision establishes authority.

## Expected report output

A task header with ID, goal, linked sources, work type, baseline, intended outcome, and approval status.

## Completion and quality checks

Do not combine unrelated architectural changes into one goal or define success as edit these files without explaining the desired outcome.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
