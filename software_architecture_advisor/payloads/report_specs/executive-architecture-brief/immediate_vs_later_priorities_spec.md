# Immediate versus later priorities

**Section:** 01 · Executive architecture brief  
**Specification ID:** `AR-01-05`  
**Customer question:** What should we address now, plan next, and deliberately leave alone?

## What to include

- Group actions into immediate containment, near-term improvement, later investment, and explicitly deferred items.
- Explain the urgency trigger, prerequisites, and expected outcome for each item.
- Identify no-regret actions and decisions that should wait for additional evidence.
- Link priorities to recommendation IDs, responsible roles, and measurable completion conditions.

## Why this matters

Customers need a feasible starting point, not an undifferentiated backlog. Explicit deferral also protects delivery capacity by showing which imperfections do not currently justify intervention.

## Evidence to use

Use the risk register, customer roadmap and constraints, recommendation dependencies, effort ranges, and unresolved verification tasks. Mark absent scheduling inputs as unknown.

## Expected report output

A now/next/later/defer table with rationale, dependencies, owner status, success measure, and links to detailed work.

## Completion and quality checks

Do not invent calendar commitments or assign people without confirmation. Distinguish urgent verification from urgent code change.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
