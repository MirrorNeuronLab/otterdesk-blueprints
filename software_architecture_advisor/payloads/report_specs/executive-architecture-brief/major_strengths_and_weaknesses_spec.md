# Major strengths and weaknesses

**Section:** 01 · Executive architecture brief  
**Specification ID:** `AR-01-03`  
**Customer question:** What should we preserve, and what currently obstructs our goals?

## What to include

- Select a small set of consequential strengths and weaknesses, tied to the system purpose and agreed quality goals.
- Explain each observation through a concrete mechanism, affected workflow, or architectural boundary.
- Identify the constraints under which a weakness may be a reasonable tradeoff.
- Link each summary item to a detailed finding and identify strengths that proposed changes must preserve.

## Why this matters

A balanced assessment prevents unnecessary rewrites and makes recommendations more credible. It also stops a narrow improvement from accidentally removing a property that already works well.

## Evidence to use

Use corroborated findings from structural, workflow, reliability, performance, and evolutionary analysis. Include operational evidence and documented constraints when available.

## Expected report output

A concise strengths-and-weaknesses table: observation, evidence, consequence, relevant constraint, and preserve-or-improve action.

## Completion and quality checks

Avoid praise based only on fashionable technology and criticism based only on size or style. Every listed item must matter to an identified stakeholder outcome.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
