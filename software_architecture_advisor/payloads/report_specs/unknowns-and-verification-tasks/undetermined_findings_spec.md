# Undetermined findings

**Section:** 22 · Unknowns and verification tasks  
**Specification ID:** `AR-22-01`  
**Customer question:** Which important questions could not be answered from the available evidence?

## What to include

- List unresolved questions and identify the finding or decision they affect.
- Explain whether the issue is missing evidence, conflicting evidence, unsupported analysis, or unreviewed scope.
- State what is known without extending it into an unsupported conclusion.
- Identify the smallest useful verification step and the consequence of acting before resolution.

## Why this matters

Customers need to distinguish a clean bill of health from an incomplete review. A precise unknown is actionable and prevents false reassurance from gaps in repository or runtime visibility.

## Evidence to use

Use analysis coverage, unsupported-language notes, failed or unavailable observations, and contradictions in the evidence register.

## Expected report output

An unresolved-question register with question ID, affected decision, known facts, reason unresolved, impact, and next check.

## Completion and quality checks

Do not describe something as absent merely because it was not found in the analyzed scope. Unknown, not applicable, not analyzed, and verified absent are different statuses.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
