# Assumptions register

**Section:** 22 · Unknowns and verification tasks  
**Specification ID:** `AR-22-03`  
**Customer question:** Which unverified premises are influencing the report’s conclusions?

## What to include

- Record each material assumption with a stable ID, rationale, and whether it came from the customer or the reviewer.
- Link assumptions to affected findings, estimates, scenarios, and recommendations.
- Describe how the conclusion changes if an assumption is false or outside its expected range.
- Assign a verification approach, owner status, and review trigger or expiry condition.

## Why this matters

Customers need to see which decisions depend on facts that have not yet been established. An assumption register makes it possible to revise the report efficiently when new information arrives.

## Evidence to use

Use explicitly stated scenario inputs, documentation gaps, customer-provided premises, and modeling choices. Do not relabel known contradictory facts as assumptions.

## Expected report output

An assumptions table with ID, statement, origin, affected decisions, sensitivity, verification, and status.

## Completion and quality checks

Do not bury material assumptions only in footnotes or present them as facts in the executive summary. Ensure numbers and recommendations reference the premises they rely on.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
