# Next measurements and verification tasks

**Section:** 22 · Unknowns and verification tasks  
**Specification ID:** `AR-22-04`  
**Customer question:** What should we check next to reduce the most consequential uncertainty?

## What to include

- Prioritize verification tasks by decision value, risk, effort, and dependencies.
- For each task, state the question, hypothesis, method, required inputs, and safe execution scope.
- Define expected evidence, decision criteria, possible outcomes, and how each outcome changes the recommendation.
- Name the responsible role or proposed owner and record prerequisites and access approvals.

## Why this matters

Customers need a route from uncertainty to action. A decision-linked verification backlog avoids open-ended investigation and clarifies when enough evidence exists to choose an architectural response.

## Evidence to use

Use unresolved findings, missing runtime inputs, assumptions, counterevidence, and pending option decisions.

## Expected report output

A verification backlog with task ID, linked decision, question, method, evidence artifact, acceptance condition, owner status, and next decision.

## Completion and quality checks

Do not make measurement a substitute for a decision already supported by sufficient evidence. Specify stop conditions and do not report a proposed experiment as completed.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
