# Minimal intervention option

**Section:** 17 · Alternative target architectures  
**Specification ID:** `AR-17-01`  
**Customer question:** What is the smallest change that reduces the immediate risk?

## What to include

- Select a bounded set of containment or cleanup actions addressing the highest-priority findings.
- Describe what remains unchanged and which residual risks the option accepts.
- Identify prerequisites, operational steps, validation, and reversal where feasible.
- Estimate effort as an explicit range or qualitative band tied to known work and assumptions.

## Why this matters

Customers often need progress without interrupting current delivery. A minimal option makes the tradeoff between near-term risk reduction and remaining structural limitations explicit.

## Evidence to use

Use prioritized findings, feasible controls, dependency analysis, current delivery constraints, and available implementation knowledge.

## Expected report output

An option card with scope, actions, preserved architecture, expected benefit, residual risk, effort basis, and validation.

## Completion and quality checks

Do not label an option low effort solely because it changes few files. Include operational work, data repair, testing, and any accepted risk that will need future attention.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
