# Option tradeoffs and selection

**Section:** 17 · Alternative target architectures  
**Specification ID:** `AR-17-04`  
**Customer question:** How do the options compare under the customer’s actual priorities and constraints?

## What to include

- Compare minimal intervention, boundary cleanup, restructuring, and retaining the current architecture.
- Use explicit criteria such as risk reduction, delivery disruption, effort, operating cost, scalability, and reversibility.
- Expose assumptions, confidence, constraint violations, and tradeoffs instead of hiding them in a single score.
- Provide a conditional recommendation, decision owner, and evidence or trigger that would change the choice.

## Why this matters

Customers need a decision they can defend and revisit. A transparent comparison makes it clear which option fits today’s constraints and when another option would become preferable.

## Evidence to use

Use the option cards, customer-stated priorities, effort and impact assessments, and validated technical constraints.

## Expected report output

A comparison matrix and short decision memo with chosen or provisional option, rationale, rejected alternatives, assumptions, and revisit triggers.

## Completion and quality checks

Do not invent stakeholder preferences or precise returns. Keep dimensions comparable, explain any weighting, and distinguish an analyst recommendation from an approved decision.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
