# 17. Alternative target architectures

Offer comparable intervention options rather than a single prescriptive redesign, including the consequences of retaining the current architecture.

This section contains **4 aspect specifications**. Each defines
what the report should contain, why the content matters, what evidence to use,
the expected output, and the completion checks.

## Aspect specifications

| ID | Aspect | Customer question |
| --- | --- | --- |
| `AR-17-01` | [Minimal intervention option](minimal_intervention_option_spec.md) | What is the smallest change that reduces the immediate risk? |
| `AR-17-02` | [Boundary cleanup option](boundary_cleanup_option_spec.md) | What targeted boundary work would improve maintainability without wholesale restructuring? |
| `AR-17-03` | [Architectural restructuring option](architectural_restructuring_option_spec.md) | What broader redesign could address long-term structural requirements? |
| `AR-17-04` | [Option tradeoffs and selection](option_tradeoffs_and_selection_spec.md) | How do the options compare under the customer’s actual priorities and constraints? |

## Reporting rule

Evaluate applicability and available evidence before populating an aspect.
Do not fill a missing observation with a plausible claim. Reuse canonical finding
IDs when this section interprets evidence also used elsewhere.
