# Priority and ordering

**Section:** 18 · Concrete prioritized recommendations  
**Specification ID:** `AR-18-07`  
**Customer question:** Which recommendations should be undertaken first, and what must precede them?

## What to include

- Prioritize actions using impact, urgency, confidence, effort, dependencies, and reversibility.
- Explain the ordering and distinguish containment, investigation, and structural improvement.
- Identify prerequisites, competing options, parallel work, and deliberately deferred recommendations.
- State which customer constraints or new evidence would change the ordering.

## Why this matters

Customers need a feasible sequence, not a ranked list that ignores prerequisites. Transparent ordering makes it possible to start useful work while avoiding premature or mutually incompatible changes.

## Evidence to use

Use finding impact, effort assessments, option decisions, roadmap dependencies, and supplied delivery constraints.

## Expected report output

A prioritized recommendation register with stable IDs, rationale, dependency links, action type, owner status, and defer-or-start decision.

## Completion and quality checks

Do not rank severity by certainty alone or count correlated findings repeatedly. Separate urgency to investigate from urgency to implement, and show the policy behind any composite score.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
