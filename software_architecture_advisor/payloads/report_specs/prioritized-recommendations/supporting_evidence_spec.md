# Supporting evidence for a recommendation

**Section:** 18 · Concrete prioritized recommendations  
**Specification ID:** `AR-18-02`  
**Customer question:** What evidence supports this finding and the proposed response?

## What to include

- Link the finding to concrete source, graph, history, runtime, test, or incident evidence.
- Explain how each evidence item supports the observation or proposed mechanism.
- Include relevant counterevidence, uncertainty, and scope limitations.
- Distinguish evidence that a problem exists from evidence that the recommendation will improve it.

## Why this matters

A customer needs to audit both the diagnosis and the proposed action. Clear linkage prevents an appealing redesign from being presented as proven simply because a nearby problem was observed.

## Evidence to use

Use the canonical evidence register and claim IDs from the evidence-and-confidence section, preserving versions and locators.

## Expected report output

A concise evidence panel with claim-to-evidence links, supporting excerpts or paths, counterevidence, and confidence rationale.

## Completion and quality checks

Do not invent counts or copy the same unsupported claim across multiple artifacts as corroboration. Repeated representations of one source are not independent evidence.

Apply the [shared report conventions](../REPORT_CONVENTIONS.md), including
claim-level traceability, confidence, scope, and explicit handling of missing
evidence. This file specifies required content; it does not assert that an
analysis or test has already been performed.
