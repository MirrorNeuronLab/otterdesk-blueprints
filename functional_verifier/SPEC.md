# Functional verifier contract

Trace analysis-document requirements to generated tests and implementation symbols. Compare the same protected case on both revisions. Inspect tests disabled or weakened by a change. Protected JSON Schema acceptance criteria can generate boundary and invalid-input cases and show which cases catch a removed constraint.

The standalone workflow captures staged UTF-8 source, executes the approved scope, and publishes JSON and Markdown plus an optional local HTML view. Its collaborative role is `functional` in the `mn.verification.v1.assignment` and `mn.verification.v1.result` contracts. Source identity, plan, run, check and attempt must match.

A passing check needs at least one verified observation. The report lists excluded, blocked and inconclusive work. Pinned external evidence must match the selected suite, cases, target and subject. A retry preserves the first attempt. A changed candidate requires a fresh run. Scope and evidence are confidential and review-only.
